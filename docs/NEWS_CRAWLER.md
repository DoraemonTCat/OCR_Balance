# News Crawler — ชั้นดึงเว็บ

ดึงข่าวจากแหล่งที่ตั้งไว้ แล้วคืนข้อความที่ล้างแล้วเป็น JSON
**ไม่แตะฐานข้อมูล ไม่นับ keyword ไม่มี framework** — สองอย่างหลังเป็นงานฝั่ง backend

ตรงตามคู่มือ *News Crawler สำหรับ Junior Dev* ขั้น 1–2 (คู่มือหน้า 3)

---

## รันยังไง

```bash
pip install -r requirements.txt
```

```bash
python -m workers.crawler.cli
```

ดึงทุกแหล่งที่สถานะ `ready` (21 แหล่ง) นับคำสำคัญจาก `workers/crawler/keywords.json`
แล้วเขียน `data/crawl/keywords_<เวลา>.json`

ตัวเลือกอื่น:

```bash
python -m workers.crawler.cli --max-articles 10
```

```bash
python -m workers.crawler.cli --only "US FDA"
```

```bash
python -m workers.crawler.cli --status all
```

ใช้ไฟล์คำสำคัญอื่น:

```bash
python -m workers.crawler.cli --keywords path/to/keywords.json
```

นับเฉพาะข่าวที่เผยแพร่ภายใน 1 วันล่าสุด:

```bash
python -m workers.crawler.cli --since-days 1
```

เทสต์ (ไม่ยิงเว็บจริง) — รันได้เลยไม่ต้องมี pytest:

```bash
python tests/test_crawler.py
```

ถ้าติดตั้ง pytest ไว้แล้วจะใช้แบบนี้ก็ได้:

```bash
python -m pytest tests/test_crawler.py -v
```

## สัญญาข้อมูล — แหล่งข่าวที่ส่งเข้ามา

**แหล่งข่าวจริงมาจากฐานข้อมูลของผู้เรียก ไม่ใช่จากไฟล์ในโปรเจ็กต์นี้**

`workers/crawler/sources.json` เป็นเพียงข้อมูลตั้งต้นสำหรับทดลองรันและเทสต์
เมื่อใช้งานจริงให้อ่านแถวจากฐานข้อมูลแล้วส่ง list ของ dict เข้า `run()` โดยตรง

### ฟิลด์ที่ต้องส่ง

| ฟิลด์ | บังคับ | ชนิด | ค่าปริยาย | ความหมาย |
|---|---|---|---|---|
| `name` | ✓ | str | — | ชื่อแหล่งข่าว ใช้อ้างอิงในผลลัพธ์และข้อความผิดพลาด |
| `url` | ✓ | str | — | URL หน้ารวมข่าว หรือ URL ของ feed |
| `kind` | | str | `"html"` | `"html"` = แกะลิงก์จากหน้าเว็บ · `"rss"` = อ่าน RSS/Atom |
| `link_pattern` | | str \| None | `None` | regex คัดลิงก์บทความ ใช้เฉพาะ `kind="html"` |
| `max_articles` | | int | `30` | จำนวนบทความสูงสุดต่อแหล่งต่อรอบ |
| `max_pages` | | int | `3` | ไล่อ่านหน้าถัดไปได้กี่หน้า รวมหน้าแรก (เฉพาะ `kind="html"`) |
| `extract_full_text` | | bool | `False` | `True` = ตามเข้าไปดึงเนื้อข่าวเต็ม |
| `group` | | str \| None | `None` | ป้ายกำกับ ไม่มีผลต่อการทำงาน |
| `original_url` | | str \| None | `None` | URL หน้าเว็บที่คนเปิดดู ใช้เป็นค่า `url` ในผลนับคำ — ถ้าไม่ใส่จะใช้ `url` แทน |

ฟิลด์ที่ไม่ส่งจะถูกเติมค่าปริยายให้ ฟิลด์ที่ไม่รู้จักถูกเก็บไว้เฉย ๆ ไม่ทำให้พัง

`run()` ตรวจทุกแหล่งก่อนเริ่มยิงเว็บ ถ้าขาดฟิลด์บังคับหรือ `kind` ไม่ถูกต้อง
จะขึ้น `ValueError` พร้อมชื่อแหล่งข่าวทันที ไม่ไปพังกลางทาง

### แปลงจากฐานข้อมูลมาเรียก

```python
from workers.crawler import run

sources = [
    {
        "name": s.name,
        "url": s.url,
        "kind": s.kind,
        "link_pattern": s.link_pattern,
        "max_articles": s.max_articles,
        "max_pages": s.max_pages,
        "extract_full_text": s.extract_full_text,
        "original_url": s.original_url,
    }
    for s in CrawlSource.objects.filter(is_active=True)
]

report = run(sources)
```

### คำสำคัญก็รับมาจากฐานข้อมูลเหมือนกัน

```python
from workers.crawler import by_keyword, run

keywords = [k.keyword for k in SearchKeyword.objects.filter(is_active=True)]

report = run(sources)
counted = by_keyword(report, keywords)          # ผลแบบเรียงตามคำสำคัญ
```

`by_keyword()` รับได้ทั้ง list ของสตริง และ list ของ dict ที่มีคีย์ `keyword`
ถ้าเป็น dict จะใส่ `full_form` หรือ `aliases` เพิ่มได้ เพื่อให้จับคำที่เขียนได้หลายแบบ

### ⚠️ `extract_full_text` ต้องมีในฐานข้อมูลด้วย

ฟิลด์นี้ **ไม่มีในคู่มือ** แต่จำเป็น เพราะเป็นตัวแยกว่าแหล่งไหนดึงเนื้อข่าวเต็มได้

| ประเภทเว็บ | ค่า | เหตุผล |
|---|---|---|
| หน่วยงานกำกับดูแล (FDA, EMA, MHRA, HSA, PMDA ฯลฯ) | `True` | เป็นประกาศสาธารณะ เผยแพร่ให้นำไปใช้อยู่แล้ว |
| สำนักข่าวเชิงพาณิชย์ (Reuters, BBC, CNN, NYT ฯลฯ) | `False` | มีลิขสิทธิ์ มี paywall และมีระบบกันบอท |

**ถ้าฐานข้อมูลไม่มีคอลัมน์นี้** ทุกแหล่งจะได้ค่าปริยาย `False` คือดึงแค่หัวข้อกับย่อข่าว
ซึ่งปลอดภัยแต่ได้ข้อมูลน้อยลงมาก — แหล่งหน่วยงานกำกับดูแลควรตั้งเป็น `True`

ค่าที่เหมาะสมของแต่ละแหล่งดูได้จาก `sources.json` ซึ่งใช้เป็นข้อมูลตั้งต้นนำเข้าได้

## เรียกใช้จากโค้ด

โมดูลใน `workers/crawler/` ไม่ `import django` เลย เรียกจากชั้นใด ๆ ของโปรเจ็กต์ได้ทันที

**ทาง A — เรียกตรง (แนะนำ)**

```python
from workers.crawler import run

report = run(sources)          # ได้ dict ไม่ผ่านไฟล์
```

**ทาง B — อ่านไฟล์ JSON** (ใช้ข้อมูลตั้งต้นใน `sources.json` กับ `keywords.json`)

```bash
python -m workers.crawler.cli
```

แล้วอ่าน `data/crawl/keywords_*.json`

**เรียกทีละแหล่ง** (เช่นเมื่ออยากคุม transaction เอง)

```python
from workers.crawler import Fetcher, crawl_source

with Fetcher() as fetcher:
    result = crawl_source(source_dict, fetcher)
```

**ยกเลิกกลางรอบ** (คู่มือหน้า 4)

```python
from workers.crawler import Canceller, run

c = Canceller()
# ... อีกเธรดเรียก c.cancel() ...
report = run(sources, canceller=c)
```

`crawler` จะเช็กก่อนดึงบทความแต่ละชิ้น จึงหยุดได้โดยไม่ต้องรอจนจบ

## ผลนับคำสำคัญ

ใส่ `--keywords` แล้วจะได้ไฟล์ที่สองชื่อ `data/crawl/keywords_<เวลา>.json`
เรียงตามคำสำคัญ ไม่ใช่ตามแหล่งข่าว

```json
[
  {
    "keysword": "Voluntary Recall",
    "ref": [
      { "url": "https://www.fda.gov/safety/recalls-market-withdrawals-safety-alerts", "count": 14 },
      { "url": "https://nida.nih.gov/", "count": 0 }
    ]
  }
]
```

| ช่อง | หมายถึง |
|---|---|
| `keysword` | คำสำคัญตามที่ส่งเข้ามา |
| `url` | หน้าเว็บที่คนเปิดดูได้ — ไม่ใช่ URL ของ feed และไม่ใช่ URL บทความ |
| `count` | จำนวนครั้งที่เจอคำนั้นในทุกบทความของเว็บนั้นรวมกัน |

**ทุกคำจะมี `ref` ครบทุกแหล่งเสมอ** แหล่งที่ไม่เจอได้ `count: 0` ไม่ถูกตัดทิ้ง
คำ 28 คำ × แหล่ง 21 แหล่ง = 588 แถว

### กติกาการนับ (คู่มือหน้า 3 ขั้น 3)

| กรณี | พฤติกรรม |
|---|---|
| ตัวพิมพ์เล็ก/ใหญ่ | ไม่สน |
| คำอังกฤษ | ต้องตรงทั้งคำ และนับรูปพหูพจน์ `-s` / `-es` ด้วย |
| คำไทย | จับแบบ substring เพราะไทยไม่มีช่องว่างระหว่างคำ |
| คำที่มีวงเล็บต่อท้าย | นับแยกสองส่วน ใช้ได้ทั้งตัวย่อและคำแปล |

`Herbal adverse reactions (HARs)` นับทั้ง `Herbal adverse reactions` และ `HARs`
ส่วน `Nitrosamines (กลุ่มสารไนโตรซามีน)` นับทั้งคำอังกฤษและคำไทย

### count หมายถึงอะไรกันแน่

> **จำนวนครั้งที่เจอคำนั้น ในบทความที่ดึงมาได้ ณ เวลาที่รัน**

ไม่ใช่ "ต่อวัน" และไม่ใช่ยอดสะสม — **แต่ละรอบเริ่มนับใหม่จากศูนย์**
ขอบเขตถูกคุมด้วย `max_articles` กับ `max_pages` ไม่ได้คุมด้วยเวลา

`count` จึงลดลงได้ทั้งที่เว็บมีข่าวเพิ่ม เพราะข่าวเก่าที่มีคำนั้นหลุดออกจากหน้าแรกไป

**ถ้าต้องการความหมาย "ข่าวที่ลงใหม่"** ให้ใส่ `--since-days 1`
จะนับเฉพาะบทความที่ `published_at` อยู่ในช่วงนั้น
บทความที่ไม่มีวันที่จะถูกนับไว้ก่อน เพราะตัดทิ้งแล้วแหล่งอย่าง CNN จะหายทั้งแหล่ง

### สิ่งที่รูปแบบนี้ทำไม่ได้

`url` เป็นระดับเว็บ ไม่ใช่ระดับบทความ จึง**เทียบข้ามรอบไม่ได้**
บอกไม่ได้ว่า `count` ที่เพิ่มขึ้นมาจากข่าวใหม่ หรือจากข่าวเดิมที่ถูกนับซ้ำ

ถ้าวันหนึ่งต้องการแบบนั้น ต้องใช้ลิงก์บทความ ซึ่ง `runner.run()` คืนมาครบอยู่แล้ว
แต่ CLI ไม่ได้เขียนลงไฟล์ ผู้เรียกที่ต้องการต้องเรียก `run()` เองแล้วเก็บผลไว้
— ตรงกับตาราง `KeywordSource` ในคู่มือหน้า 2 ที่ unique บน `(keyword, link)`

### ช่องที่ต้องรู้

**`text_source`** บอกว่าข้อความมาจากไหน — ใช้ค่านี้ตีความผลการนับ keyword

| ค่า | หมายถึง |
|---|---|
| `article` | เนื้อข่าวเต็ม (เว็บหน่วยงานรัฐ) |
| `rss_summary` | แค่หัวข้อกับย่อข่าว (เว็บข่าวเชิงพาณิชย์) |
| `skipped_document` | ลิงก์ชี้ไปไฟล์ PDF/Word ไม่ได้ดึง — ดู `error` |
| `none` | ไม่มีข้อความเลย feed ต้นทางส่งมาว่าง |

ถ้าไม่ดูช่องนี้ จะงงว่าทำไมข่าว BBC เจอ keyword น้อยกว่าข่าว FDA — เพราะข้อความสั้นกว่ามาก ไม่ใช่เพราะเนื้อหาไม่เกี่ยว

**`published_at_source`** บอกว่าวันที่มาจากไหน — ใช้ตัดสินว่าเชื่อได้แค่ไหน

| ค่า | หมายถึง | ความแม่น |
|---|---|---|
| `feed` | วันที่จาก RSS/Atom | แม่นถึงระดับนาที |
| `page` | meta tag, JSON-LD หรือ `<time>` ในหน้าบทความ | แม่นถึงระดับวัน |
| `url_path` | เดาจากเส้นทางใน URL เช่น `/2026/October/` | **แม่นแค่ระดับเดือน** — วันจะเป็นวันที่ 1 เสมอ |
| `null` | หาไม่เจอ `published_at` จะเป็น `null` ด้วย | — |

ถ้าจะใช้ตัดสินว่า "ข่าวนี้ใหม่หรือเก่า" อย่าเชื่อ `url_path` ถึงระดับวัน

**`status` ของแต่ละแหล่ง** มี 3 ค่า

| ค่า | หมายถึง |
|---|---|
| `ok` | ดึงสำเร็จ |
| `blocked` | เว็บปฏิเสธ (`robots.txt` ห้าม หรือ HTTP 401/403/429) — **ไม่ใช่ระบบพัง** |
| `error` | ผิดพลาดจริง เช่น timeout |

รอบไหนมีอย่างน้อยหนึ่งแหล่งสำเร็จ = `SUCCESS` ไม่มีเลย = `FAILED` (คู่มือหน้า 3 ขั้น 4)

**`normalized: true`** — `title`, `summary`, `text` ล้างมาแล้วทั้งหมด เอาไปแมพ keyword ได้เลย ไม่ต้องล้างซ้ำ

## การหาลิงก์บทความ

`extract_links()` ค้น 2 ที่ (คู่มือหน้า 3 ขั้น 1):

1. **`<a href>`** — ลิงก์ปกติในหน้า
2. **`<script>` / JSON** — บางเว็บโหลดรายการข่าวผ่าน JavaScript ลิงก์จึงไม่อยู่ใน `<a href>` แต่ฝังเป็นข้อความใน JSON ที่ติดมากับหน้า

แต่ละลิงก์มีช่อง `found_in` บอกว่ามาจาก `anchor` หรือ `script`

ตัวกรองที่ใส่ไว้: ตัดไฟล์ประกอบหน้าเว็บทิ้ง (`.js`, `.css`, รูป, ฟอนต์) และตัดโฟลเดอร์อย่าง
`/wp-content/`, `/static/`, `/_next/` เพราะเว็บที่ไม่ได้ตั้ง `link_pattern` จะได้ขยะพวกนี้ปนมา

> **สถานะปัจจุบัน:** ค้น `<script>` แล้วยังไม่ได้ลิงก์เพิ่มจากแหล่ง HTML ที่ใช้อยู่
> เพราะเว็บที่โหลดข่าวด้วย JavaScript อย่าง BBC เราใช้ RSS แทนไปแล้ว ส่วน EMA ตรวจแล้วพบว่า
> หน้าแรกมีลิงก์ข่าวแค่ 6 ลิงก์จริง ไม่ได้ซ่อนไว้ในสคริปต์
>
> ฟีเจอร์นี้จึงเป็นตาข่ายรองรับสำหรับแหล่งข่าวที่จะเพิ่มเข้ามาทีหลัง มีเทสต์ยืนยันว่าทำงานได้จริง
>
### เดินไปหน้าถัดไป

หลังอ่านหน้ารวมข่าวหน้าแรกแล้ว `find_next_page()` จะหาลิงก์หน้าถัดไปต่อ
ไล่ได้ถึง **3 หน้า** (ปรับด้วย `--max-pages` หรือฟิลด์ `max_pages` ของแหล่งข่าว)

หาจาก `<link rel="next">` → `<a rel="next">` → ข้อความบนลิงก์ (`Next`, `ถัดไป`, `›`)
→ `aria-label` / `title` โดยเทียบข้อความแบบตรงทั้งก้อน ไม่ใช่ substring
เพราะคำว่า next โผล่ในพาดหัวข่าวได้

หยุดเมื่อครบจำนวนหน้า ครบจำนวนบทความ ไม่มีหน้าถัดไป หรือหน้าถัดไปวนกลับมาที่เดิม

**แหล่ง RSS ไม่เดินหน้าถัดไป** เพราะ feed ส่งรายการมาทีเดียวจบ

ผลจากการเปิดใช้: Health Canada 11 → 30 บทความ (3 หน้า) · FDA Device Safety 26 → 30 (2 หน้า)

> เว็บที่โหลดเนื้อหาด้วย JavaScript **ทั้งหมด** ยังดึงไม่ได้อยู่ดี เพราะ HTML ที่ได้ไม่มีแท็ก `<a>`
> เลยสักตัว (Hong Kong MDD และ สบส. เป็นแบบนี้) ต้องใช้ headless browser ซึ่งอยู่นอกขอบเขตของโมดูลนี้

## เรื่อง normalize ที่ต้องรู้

`normalize_text()` ทำ 4 อย่าง:

1. **NFC** — รวมสระ/วรรณยุกต์ที่แยกส่วน
2. **รวม "ํา" กับ "ำ"** — NFC ทำให้ไม่ได้ Unicode ไม่ถือว่าเทียบเท่า ต้องแทนที่เอง
3. **ลบ zero-width space** — ไม่ใช่แปลงเป็นช่องว่าง
4. **ยุบช่องว่างซ้ำ**

> **ต่างจาก `workers/normalizer.py` ตรงข้อ 3** ของเดิมแปลง zero-width space เป็นช่องว่าง
> ซึ่งเหมาะกับงานเทียบข้อความ OCR แต่ทำให้ keyword ไทยพัง เพราะภาษาไทยไม่มีช่องว่างระหว่างคำ
>
> `"เรียก<ZWSP>เก็บคืนยา"` → แปลงเป็นช่องว่างได้ `"เรียก เก็บคืนยา"` แล้ว keyword `"เรียกเก็บคืนยา"` จับไม่ได้

## มารยาทต่อเว็บปลายทาง

`Fetcher` คุมให้อัตโนมัติ (คู่มือหน้า 3):

- ตรวจ `robots.txt` ก่อนทุก URL แล้ว cache ผลต่อ host
- หน่วง 1 วินาทีระหว่าง request ที่ไป host เดียวกัน เว็บต่างกันดึงพร้อมกันได้
- timeout 20 วินาที · `User-Agent: HerbRiskBot/1.0`
- 401/403/429 = `BlockedError` ไม่ใช่ error ธรรมดา

มีแฟล็ก `--no-robots` ไว้ตอนทดสอบเท่านั้น **ห้ามใช้ตอนรันจริง**

## เรื่อง HTTPS บนเครื่อง Windows

เครื่องที่มีแอนตี้ไวรัสดักตรวจ HTTPS (เช่น Avast) จะสวมใบรับรองของตัวเองเข้ามา
ซึ่งไม่อยู่ใน `certifi` ที่ Python ใช้โดยปริยาย ทำให้ขึ้น `CERTIFICATE_VERIFY_FAILED`
ทั้งที่เว็บปลายทางปกติดี

แก้ด้วย `truststore` (อยู่ใน `requirements.txt`) ให้ Python อ่าน certificate store ของ Windows
**ไม่ได้แก้ด้วย `verify=False`** เพราะนั่นคือการปิดการตรวจใบรับรองทิ้งทั้งหมด
