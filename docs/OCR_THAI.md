# ภาษาไทยกับ OCR: อะไรอ่านได้ อะไรยังพลาด

เอกสารนี้บันทึกว่าระบบอ่านภาษาไทยได้แค่ไหน พร้อมหลักฐานที่วัดจริง
คนที่มาดูทีหลังจะได้ไม่ต้องไล่หาสาเหตุซ้ำ

## สรุปสั้น

- **PaddleOCR 3.3 (PP-OCRv5) มีโมเดลภาษาไทยแล้ว** (`th_PP-OCRv5_mobile_rec`)
  ค่าปริยายจึงเปลี่ยนเป็น `OCR_LANGUAGE=th` โมเดลนี้อ่านอักษรละตินและตัวเลขได้ด้วย
- เดิมเราใช้ PaddleOCR 2.9.1 ซึ่ง**ไม่มีโมเดลไทยเลย** ตอนนั้นต้องตั้งเป็น `latin`
  ช่องภาษาไทยจึงออกมาเป็นอักษรละตินมั่วๆ ถ้ายังตั้ง `latin` อยู่
  ระบบจะติดธงช่องไทยให้ตรวจทุกช่องเหมือนเดิม (ดู `form_layout.THAI_ROLES`)
- **ชื่อผู้รับยา**อ่านด้วย engine หลายตัวแล้วรวมผล (PaddleOCR + Tesseract)
  แล้วใช้คลังชื่อไทยของ PyThaiNLP ช่วยตัดสินตัวอักษรที่หน้าตาคล้ายกัน
  ดู `workers/thai_names.py`

### ทำไมชื่อยังไม่ถึง 100%

ชื่อที่ยังผิดแบ่งได้ 3 กลุ่ม ทุกกลุ่มตรวจกับภาพขยายแล้ว:

1. **ข้อมูลไม่มีอยู่ในภาพ** แถวพิมพ์ชิดเส้นตารางด้านบนมาก
   วรรณยุกต์ชั้นบนสุดจึงทับอยู่ในเส้นพอดี เช่น ่ ของ "ชื่น" และ ้ ของ "เชื้อ"
   คนที่ทำเฉลยก็ต้องเติมเองจากการสะกดที่พบบ่อย
2. **ต้นฉบับพิมพ์ต่างจากการสะกดปกติ** เช่น "เอกสิทธิ", "สมศักดิ" (ไม่มี ์)
   และ "ตวงตา" (ไม่ใช่ ดวงตา) โมเดลจะ "แก้" ให้เป็นการสะกดที่คุ้นเคย
3. **ตัวอักษรหน้าตาคล้ายกันที่ 200 dpi** เช่น ด/ต ใน "ลันดา", "ปาระมัด", "อุดร"
   และ ช/ซ/ข ซึ่ง engine ทุกตัวอ่านผิดไปทางเดียวกัน การโหวตจึงช่วยไม่ได้

ชื่อที่ engine อ่านไม่ตรงกันจะถูกตั้ง `needs_review` พร้อมเหตุผล
`issued_to: the readings of this name disagree` เกณฑ์ที่ใช้คือไม่ถึง 4 ใน 5 ของผลอ่านตรงกัน
เกณฑ์นี้จับชื่อที่ผิดได้ 32 จาก 36 ชื่อ
ส่วนชื่อที่ไม่ถูกติดธงถูกต้อง 98.7%

## วิธีอ่านบัญชีขายที่พิมพ์มา

ตารางของฟอร์มนี้มีเส้นคั่นทุกแถว ระบบจึง**ไม่ใช้ text detector ในตาราง**
แต่ตัดภาพทีละช่องตามเส้นตาราง แล้วส่งให้โมเดล recognition อ่านอย่างเดียว
ดู `workers/cell_ocr.py`

1. **หมุนหน้าให้ตั้งตรง** (`grid_detector.orient`) ถ้าหน้าสูงกว่ากว้าง
   และเส้นแนวตั้งเยอะกว่าเส้นแนวนอนมาก แปลว่าสแกนมาตะแคง
   ส่วนหน้ากลับหัวดูจากหมึก ถ้าหมึกนอกตารางอยู่ใต้ตารางมากกว่าเหนือตารางเกิน 3 เท่า แปลว่ากลับหัว
2. **ตัดภาพช่องชื่อเลยเส้นด้านบนขึ้นไป 7 px** สระบนและวรรณยุกต์ (ิ ี ่ ้ ำ)
   แตะหรือทับเส้นตาราง ถ้าตัดต่ำกว่าเส้น ความต่างระหว่าง "ศิริรำ" กับ "ศรีรา" จะหายไป
   การแก้จุดนี้จุดเดียวทำให้ชื่อถูกทั้งชื่อเพิ่มจาก 49% เป็น 75%
   ช่องอื่นยังตัดต่ำกว่าเส้น 5 px เพราะเศษเส้นจะถูกอ่านเป็น "--"
3. **ลบหมึกปากกา** (ติ๊ก วงกลม จุดสีส้ม) ดูจากความอิ่มสีและความสว่าง
   แต่ไม่ลบพิกเซลมืดที่เป็นหมึกพิมพ์ใต้รอยปากกา
4. **หัวกระดาษ**ใช้ PaddleOCR แบบ detection+recognition ตามปกติ
   แต่ลบจุดไข่ปลาออกก่อน เพื่อให้อ่านบรรทัด "ชื่อการค้า" ได้

## วิธีรวมผลอ่านชื่อ

ดู `workers/thai_names.py`

1. อ่านชื่อแต่ละชื่อ 5 รอบ ได้แก่
   - PaddleOCR (ภาพตามที่ตัดมา)
   - PaddleOCR (ปรับความสูงภาพเป็น 48 px)
   - Tesseract `tha` (tessdata_best)
   - Tesseract `tha_fast` (tessdata_fast)
   - Tesseract `tha` กับภาพขยาย 2 เท่า
2. โหวตทีละตัวอักษร (ROVER) โดยจัดเรียงผลอ่านทุกรอบเทียบกับผลของ PaddleOCR
3. ตัวอักษรในกลุ่มที่หน้าตาคล้ายกัน (ช/ซ/ข, ด/ต, ใ/ไ, บ/ป, ิ/ี, ั/้)
   ให้ character 4-gram ที่สร้างจากรายชื่อคนไทยและคำไทยของ PyThaiNLP ช่วยเลือก
4. แก้คำนำหน้าที่อ่านเพี้ยน (นาย นาง นางสาว น.ส. เด็กชาย เด็กหญิง)
   และลบเครื่องหมายวรรคตอนที่หลงมา แต่เก็บคำย่ออย่าง "ส.ต.อ." ไว้

ถ้าเครื่องไม่มี Tesseract ระบบยังทำงานได้ แต่จะเหลือผลอ่านแค่ 2 รอบจาก PaddleOCR
วิธีติดตั้ง: `.\scripts\setup_tesseract.ps1`

| ขั้น (วัดบนชื่อ 134 ชื่อที่ใช้จูน) | ถูกทั้งชื่อ |
| --- | --- |
| PaddleOCR อย่างเดียว ตัดภาพต่ำกว่าเส้น | 65/134 |
| + ตัดภาพเลยเส้นขึ้นไป | 100/134 |
| + โหวต 5 รอบ (PaddleOCR + Tesseract) | 121/134 |
| + โมเดลการสะกดชื่อไทย | 127/134 |

บนชื่อทั้งหมด 452 ชื่อ ได้ 92.4% ตามตารางด้านบน
ตัวเลขนี้ต่ำกว่าชุดที่ใช้จูน ซึ่งเป็นเรื่องปกติ

## รันการวัดผลซ้ำ

```powershell
.venv\Scripts\python.exe eval\run_pipeline.py eval\sample.pdf eval\out\result.json
.venv\Scripts\python.exe eval\compare.py eval\out\result.json --show 60
.venv\Scripts\python.exe eval\report.py eval\out\result.json eval\results\เฉลย.xlsx eval\results\ผลเทียบ.xlsx
```

`eval/key/pNN.json` คือเฉลย ส่วน `eval/compare.py` จับคู่แถวด้วยเลขบัตร

## การระบุชนิดฟอร์ม

ระบบระบุชนิดฟอร์มจาก**สัดส่วนความกว้างคอลัมน์**ที่วัดจากเส้นตารางจริง
ไม่ได้อ่านจากชื่อฟอร์ม ดู `workers/form_layout.py`
ส่วนรหัสฟอร์มที่พิมพ์ไว้มุมซ้ายบนจะอ่านด้วย OCR
แล้วจับคู่กับรหัสที่รู้จัก (`FormLayout.variants`) เพราะ OCR มักทำจุดใน "บ.ว.จ." หาย

## ข้อควรรู้เรื่องลายมือ (วัดสมัย PaddleOCR 2.9.1 / `latin` ยังไม่ได้วัดซ้ำ)

| ตัวเลขยอดถูก | 144/180 (80%) |
| **วันที่ถูก** | **16/45 (36%)** |
| วันที่ผิดแต่ยังมีค่า | 9 |

ค่าที่ "เป็นไปไม่ได้" ถูกกันออกไปแล้วหนึ่งชนิด: เวลาคนเขียนขีดฆ่าแก้ตัวเลข
ทั้งค่าเก่าและค่าใหม่จะอยู่ในช่องเดียวกัน (`"39 o 410"`) การลบช่องว่างทิ้งทำให้
ได้ `390410` ซึ่งไม่มีใครเขียน ตอนนี้ระบบตรวจเจอและคืนค่าว่างพร้อมเหตุผลแทน —
ดู `balance_normalizer.holds_two_figures`

ที่ยังกันไม่ได้คือกรณีที่ OCR อ่านเลขผิดแต่รูปแบบยังถูกต้อง เช่น `1,000`
อ่านเป็น `12,000` ไม่มีอะไรในโครงสร้างบอกได้ว่าผิด มีแต่การตรวจยอดที่จับได้

วันที่ยังเป็นจุดอ่อนที่สุด เพราะขีด `/` ที่คั่น วัน/เดือน/ปี เป็นเส้นบางที่สุด
บนฟอร์ม detector มักไม่จับ หรือจับเป็นเลข `1`/`7` ทำให้ `16/3/69` กลายเป็น
`16369` หรือ `163769` ระบบจึงใช้ข้อเท็จจริงว่า**รายงานพวกนี้เป็นรายเดือน**
มากำกับ: เดือนและปีมาจากวันที่ที่อ่านได้สะอาดทั้งเอกสาร แล้วกู้เฉพาะ "วัน"
จากตัวเลขในช่อง โดยยอมเฉพาะกรณีที่ตีความได้ทางเดียว —
ดู `balance_parser.settle_dates`

การตรวจสอบยอด (`ยอดยกมา + รับ − จ่าย = คงเหลือ`) คือเครื่องมือที่ดีที่สุดที่มี
เพราะเป็นการยืนยันตัวเลขสี่ช่องด้วยกันเองโดยไม่ต้องพึ่งข้อมูลภายนอก —
ดู `balance_parser._check_balance`

**สรุป: ผลลัพธ์ชุดนี้ต้องผ่านสายตาคนก่อนนำไปใช้** ระบบออกแบบให้บอกได้ว่า
แถวไหนน่าเชื่อถือ (`needs_review = false`) ไม่ได้ออกแบบให้เชื่อได้ทั้งหมด
