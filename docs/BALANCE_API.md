# Balance API — สัญญาการเรียกใช้

บริการนี้รับไฟล์ PDF ของบัญชี/รายงานวัตถุออกฤทธิ์ที่เขียนด้วยลายมือ
อ่านเฉพาะ**ข้อมูลในตาราง** แล้วคืนค่าที่อ่านได้กลับไป
มันไม่เปรียบเทียบกับฐานข้อมูลใด และไม่ตัดสินใจอะไรแทนผู้เรียก

Base URL: `http://localhost:3004/api/v1/balance`

---

## POST /documents

อัปโหลด PDF หนึ่งไฟล์ ระบบจะอ่านให้เสร็จ**ก่อน**ตอบกลับ

`multipart/form-data`

| field | required | หมายเหตุ |
| --- | --- | --- |
| `file` | ✓ | ต้องเป็น `.pdf` |
| `uploaded_by` | | ชื่อผู้เรียก เก็บไว้ดูย้อนหลัง |

```bash
curl -X POST http://localhost:3004/api/v1/balance/documents \
  -F "file=@ledger.pdf" \
  -F "uploaded_by=go-backend"
```

**เวลาที่ใช้: ประมาณ 6–7 วินาทีต่อหน้า** (วัดจากเอกสาร 8 หน้า = 52 วินาที)
ผู้เรียกต้องตั้ง timeout ให้พอ เอกสารเกิน `services.MAX_PAGES` (50 หน้า)
จะถูกปฏิเสธ — ขนาดนั้นควรใช้คิวงานแทน

### อ่านผลด้วยตา: `?pretty`

ปริยาย JSON ออกมาเป็น**บรรทัดเดียวไม่มีช่องว่าง** เพราะออกแบบให้โปรแกรมอ่าน
ถ้าจะเปิดดูเองให้เติม `?pretty` ต่อท้าย URL:

```bash
curl.exe -X POST "http://localhost:3004/api/v1/balance/documents?pretty" -F "file=@ledger.pdf" -o result.json
```

ใส่ค่าอะไรก็ได้ (`?pretty`, `?pretty=1`) ข้อมูลเหมือนกันทุกประการ
ต่างแค่การจัดบรรทัด และภาษาไทยจะออกมาเป็นตัวอักษรไทยไม่ใช่ `\uXXXX`

### 201 Created

`entries` คือ **12 คอลัมน์** ที่ตกลงกันไว้ หนึ่ง object ต่อหนึ่งแถวในบัญชี

ตัวอย่างด้านล่างเป็นผลจริงจากไฟล์ตัวอย่าง 4 หน้า (ตัด `page_summary` เหลือ 2 หน้า
และ `entries` เหลือแถวแรกแถวเดียว)

```json
{
  "document_id": "b2ab5987-512e-418f-9855-54dc1261a575",
  "file_name": "Sample.pdf",
  "page_count": 4,
  "status": "COMPLETED",
  "ocr_language": "latin",
  "entry_count": 18,
  "review_count": 2,
  "processing_ms": 1780,
  "page_summary": [
    {
      "page": 1,
      "form": "บ.ย.ส. ๒/ว.จ. ๒-จ๑",
      "rows": 4,
      "skew": 0.36,
      "source": "TEXT_LAYER",
      "confidence": 1.0,
      "error": ""
    },
    {
      "page": 2,
      "form": "ร.ย.ส. ๒/ว.จ. ๒-จ๑",
      "rows": 5,
      "skew": 0.52,
      "source": "TEXT_LAYER",

      "error": ""
    }
  ],
  "entries": [
    {
      "sequence": 1,

```

### 12 คอลัมน์

**คีย์ใน JSON เป็นภาษาอังกฤษ ไม่ใช่หัวคอลัมน์ภาษาไทย** ตั้งใจให้ต่างกัน —
หัวคอลัมน์ไทยเป็นของไฟล์ Excel ซึ่งต้องตรงกับ `ฟอแมทตาราง OCR.xlsx` ทุกตัวอักษร
รวมถึงการขึ้นบรรทัดใหม่ ส่วนคีย์ JSON คือตัวระบุที่โปรแกรมอ่าน
คีย์ที่มีขึ้นบรรทัดใหม่กับเครื่องหมาย `/` อยู่ข้างในทำให้ผู้เรียกทุกรายต้องใส่เครื่องหมายคำพูด
และไม่มีใคร autocomplete ได้

นิยามอยู่ที่ `OUTPUT_KEYS` และ `OUTPUT_COLUMNS` ใน `workers/balance_export.py`
ทั้งสองผูกกันด้วย assert จึงหลุดจากกันไม่ได้

| # | คีย์ JSON | หัวคอลัมน์ใน Excel | ที่มา |
| --- | --- | --- | --- |
| 1 | `sequence` | `ลำดับ` | ระบบนับให้ — **เริ่มใหม่ทุกครั้งที่เปลี่ยนแบบฟอร์ม** |
| 2 | `date` | `วัน เดือน ปี` | ข้อความตามที่ฟอร์มเขียน |
| 3 | `generic_name` | `ชื่อ/ความแรงของวัตถุออกฤทธิ์` | ✓ |
| 4 | `trade_name` | `ชื่อการค้า` | ✓ |
| 5 | `batch_no` | `เลขที่/รุ่นที่/ครั้งที่ผลิต` | ✓ |
| 6 | `received_from` | `ได้มาจาก` | ✓ |
| 7 | `issued_to` | `จำหน่ายให้ › ชื่อ-นามสกุลผู้รับยา` | ✓ |
| 8 | `recipient_id` | `จำหน่ายให้ › เลขที่บัตรประจำตัวประชาชน/…` | ✓ (เฉพาะฟอร์ม บ.ย.ส.) |
| 9 | `balance_brought` | `จำนวน › ยกมา` | ✓ ตัวเลข |
| 10 | `received` | `จำนวน › รับ` | ✓ ตัวเลข |
| 11 | `issued` | `จำนวน › จ่าย` | ✓ ตัวเลข |
| 12 | `balance` | `จำนวน › คงเหลือ` | ✓ ตัวเลข |

ช่องตัวเลขที่ฟอร์มเว้นว่างไว้จะเป็น `null` ไม่ใช่ `0` — เว้นว่างกับศูนย์คนละความหมาย

> **`date` เป็นข้อความ ไม่ใช่ค่าวันที่** เพราะฟอร์มใช้ตัวย่อเดือนไทย
> และฟอร์ม ร.ย.ส. ใส่**ช่วงวันที่**ได้ เช่น `3-31 ม.ค. 68` ซึ่งเป็นการสรุป
> การจ่ายทั้งเดือนในบรรทัดเดียว บีบให้เป็นวันที่เดียวจะทำให้ความหมายหาย

### page_summary

หนึ่ง object ต่อหนึ่งหน้า

| คีย์ | หมายถึง |
| --- | --- |
| `page` | เลขหน้า เริ่มที่ 1 |
| `form` | แบบฟอร์มที่ระบุได้ |
| `rows` | จำนวนแถวที่อ่านได้จากหน้านั้น |
| `skew` | องศาที่หน้าเอียง ระบบหมุนกลับให้แล้ว |
| `source` | `TEXT_LAYER` = อ่านข้อความที่ฝังในไฟล์ แม่นมาก · `OCR` = สแกน แม่นน้อยกว่ามาก |
| `confidence` | ความมั่นใจของหน้านั้น — `TEXT_LAYER` ได้ `1.0` เสมอ |
| `error` | หน้าที่อ่านไม่ได้เลย |

### แถวไหนเชื่อได้

คำตอบไม่ได้บอกรายแถว มีแต่ `review_count` ที่บอกจำนวนรวม
**ทั้ง `POST /documents` และ `GET /documents/{document_id}` ก็ไม่บอก**

| | |
| --- | --- |
| `review_count` | จำนวนแถวที่ระบบไม่มั่นใจ |
| `page_summary[].source` | ดูตารางด้านบน |
| `page_summary[].error` | หน้าที่อ่านไม่ได้เลย |

**ถ้า `review_count` เท่ากับ `entry_count` แปลว่าทุกแถวต้องให้คนดู** ซึ่งเป็นเรื่องปกติ
สำหรับไฟล์ลายมือ

**อยากรู้ว่าแถวไหน ต้องดาวน์โหลด Excel** ที่ `GET /documents/{document_id}/export.xlsx`
แถวที่ไม่มั่นใจจะถูกลงสีไว้ และเหตุผลรายแถวอยู่ในชีตที่สอง

เหตุผลรายแถวกับคอลัมน์ที่ฟอร์แมตนี้ไม่มีช่องให้ (หน่วย, หมายเหตุ) ถูกอ่าน
และเก็บในฐานข้อมูลครบ แต่ไม่ได้ส่งออกมาทาง API

### 400 Bad Request
ไม่ได้แนบไฟล์ หรือไฟล์ไม่ใช่ PDF

### 422 Unprocessable Entity
ไฟล์เปิดไม่ได้ / ติดรหัสผ่าน / หน้าเกินกำหนด

```json
{"error": {"code": "INVALID_PDF", "message": "cannot open PDF: …"},
 "document_id": "…"}
```

เอกสารยังถูกบันทึกไว้ด้วย `status: "FAILED"` เรียกดูย้อนหลังได้

## GET /documents/{document_id}

คืนเอกสารพร้อมทุกแถว โครงสร้างเดียวกับ 201 ข้างบน — `404` ถ้าไม่พบ

## GET /documents

รายการเอกสารที่เคยส่งเข้ามา (ไม่มี `entries`)

| query | |
| --- | --- |
| `status` | `PENDING` / `PROCESSING` / `COMPLETED` / `FAILED` |
| `search` | ค้นจากชื่อไฟล์ |
| `limit` | ปริยาย 50 สูงสุด 200 |

```json
{"items": [ … ]}
```

## GET /documents/{document_id}/export.xlsx

ไฟล์ Excel ตามรูปแบบที่ตกลงกันไว้ 3 ชีต

| ชีต | เนื้อหา |
| --- | --- |
| `Output` | 12 คอลัมน์ตาม `ฟอแมทตาราง OCR.xlsx` เป๊ะ ๆ แถวที่ไม่มั่นใจลงสีไว้ |
| `สรุปรายหน้า` | ผลรายหน้า รวมหน้าที่อ่านไม่ได้ |

> ชีต `Output` มีเพียง 4 คอลัมน์ที่ฟอร์มให้ข้อมูลได้ อีก 12 คอลัมน์เป็นของ
> ระบบใบคำขอซื้อ ซึ่งไม่มีอยู่ในเอกสารนี้ จึงเว้นว่างและลงสีเทาไว้
> ข้อมูลที่ฟอร์มมีจริงอยู่ในชีต `ข้อมูลจากตาราง` — ดู `workers/balance_export.py`

## POST /documents/{document_id}/reprocess

อ่านไฟล์เดิมซ้ำโดยไม่ต้องอัปโหลดใหม่ (ใช้หลังแก้ parser)
แถวเดิมจะถูกแทนที่ ไม่ใช่เพิ่มเข้าไป

## ฟอร์มที่รองรับ

| `form_code` | ชื่อเต็ม | คอลัมน์ |
| --- | --- | --- |
| `ร.ว.จ ๗/๔` | รายงานผลการดำเนินกิจการเกี่ยวกับวัตถุออกฤทธิ์ฯ | 12 |
| `บ.ว.จ ๗/๔-ขพ` | บัญชีจำหน่ายวัตถุออกฤทธิ์ฯ | 12 |
| `ร.ค.-๔` | รายงานเกี่ยวกับการมีไว้ในครอบครองวัตถุออกฤทธิ์ฯ | 11 |

หน้าที่ไม่ตรงกับฟอร์มใดจะถูกข้าม และบันทึกเหตุผลใน `page_summary`
โดยไม่ทำให้ทั้งเอกสารล้มเหลว — การเพิ่มฟอร์มใหม่ทำที่ `workers/form_layout.py`

## ข้อจำกัดที่ต้องรู้ก่อนใช้

อ่าน [OCR_THAI.md](OCR_THAI.md) ก่อน โดยสรุป: **ช่องภาษาไทยอ่านไม่ได้**
เพราะ PaddleOCR 2.9.1 ไม่มีโมเดลไทย ช่องเหล่านั้นจะมีค่าที่ดูเหมือนข้อความปกติ
แต่เชื่อไม่ได้ และแถวนั้นจะถูกนับรวมใน `review_count` เสมอ

ใน 12 คอลัมน์ที่ API คืนมา ช่องที่ได้รับผลคือ `issued_to`
ส่วน `unit` กับ `remark` ถูกอ่านและเก็บในฐานข้อมูลแต่ไม่ได้ส่งออกมา
ดูได้จากไฟล์ Excel
