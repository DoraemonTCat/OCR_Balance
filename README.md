# OCR_Balance

บริการอ่านตาราง (OCR) สำหรับ**บัญชีและรายงานวัตถุออกฤทธิ์ในประเภท ๓ หรือ ๔**
ที่กรอกด้วยลายมือและสแกนมาเป็น PDF — อ่านเฉพาะข้อมูลในตาราง แล้วคืนค่าออกมาเป็น
JSON และไฟล์ Excel

ขอบเขตของบริการนี้คือ**ตัวระบบ OCR อย่างเดียว** — รับไฟล์ อ่าน คืนค่า
ไม่เปรียบเทียบกับฐานข้อมูลใด ไม่ตัดสินใจอะไรแทนผู้เรียก และไม่มีคิวงาน
ส่วนที่เหลือ (frontend, business logic, deployment) อยู่นอกโปรเจกต์นี้

## เอกสารที่รองรับ

| แบบฟอร์ม | ชื่อเต็ม | คอลัมน์ |
| --- | --- | --- |
| ร.ว.จ ๗/๔ | รายงานผลการดำเนินกิจการเกี่ยวกับวัตถุออกฤทธิ์ฯ | 12 |
| บ.ว.จ ๗/๔-ขพ | บัญชีจำหน่ายวัตถุออกฤทธิ์ฯ | 12 |
| ร.ค.-๔ | รายงานเกี่ยวกับการมีไว้ในครอบครองวัตถุออกฤทธิ์ฯ | 11 |

## เริ่มใช้งาน

```powershell
# 1. venv + dependencies + .env + CA bundle (Python 3.10-3.12 เท่านั้น;
#    paddlepaddle 2.6.2 ยังไม่มี wheel สำหรับ 3.13)
.\scripts\setup.ps1 -Dev

# 2. ตั้งค่า DB_* ใน .env แล้วสร้างตาราง
.\scripts\migrate.ps1

# 3. รัน
.\scripts\local-run.ps1          # http://localhost:3004
```

ถ้ายังไม่มี PostgreSQL บนเครื่อง ใช้ SQLite รันดูก่อนได้เลย:

```powershell
.\scripts\migrate.ps1 -Sqlite
.\scripts\local-run.ps1 -Sqlite
```

ยิงเอกสารเข้าไป:

```bash
curl -X POST http://localhost:3004/api/v1/balance/documents \
  -F "file=@ledger.pdf" -F "uploaded_by=go-backend"
```

ได้ JSON กลับมาโดยที่ `entries` คือ **16 คอลัมน์ตาม `ตัวอย่าง Colume.xlsx`**
(ชื่อคีย์และลำดับตรงกับหัวคอลัมน์ในไฟล์ Excel ทุกตัวอักษร) ส่วน `ledger` คือ
ข้อมูลที่ฟอร์มมีจริงแต่ 16 คอลัมน์ไม่มีที่ให้ใส่ — ยอดยกมา/รับ/จ่าย/คงเหลือ
และ `needs_review` ที่บอกว่าแถวไหนเชื่อได้

สัญญาการเรียกใช้ทั้งหมดอยู่ที่ [docs/BALANCE_API.md](docs/BALANCE_API.md)

## อ่านก่อนเชื่อผลลัพธ์

**PaddleOCR 2.9.1 ไม่มีโมเดลภาษาไทย** ช่องที่เขียนเป็นภาษาไทย
(ชื่อผู้รับยา, หน่วย, หมายเหตุ รวมถึงหัวฟอร์มทั้งหมด) **อ่านไม่ได้**
และจะคืนค่าที่ดูเหมือนข้อความปกติแต่เป็นขยะ — `"ชลิดา จันทร์สด"` กลายเป็น
`"t@on SunScQ"` แถวเหล่านั้นจึงถูกตั้ง `needs_review = true` เสมอ

ความแม่นที่วัดได้จริง เทียบกับเฉลยที่นับจากภาพสแกนทีละแถว
(เอกสารตัวอย่าง 8 หน้า มี 45 แถวจริง):

| | |
| --- | --- |
| ระบุชนิดฟอร์มถูก | 8/8 หน้า |
| จำนวนแถวที่สกัดได้ | 46 (7 ใน 8 หน้าได้จำนวนตรงเป๊ะ) |
| ตัวเลข ยกมา/รับ/จ่าย/คงเหลือ ถูก | **80%** (144/180) |
| วันที่ถูก | **36%** (16/45) |
| **แถวที่ถูกตั้ง `needs_review`** | **46/46** |
| เวลา | ~18 วินาที/หน้า |

**ทุกแถวถูกตั้ง `needs_review` บนเอกสารชุดนี้** เพราะอย่างน้อยหนึ่งช่อง
อ่านไม่ได้หรือต้องเดา — ส่วนใหญ่คือวันที่และช่องภาษาไทย
ผลลัพธ์ชุดนี้จึงใช้เป็น **"ร่างที่ต้องให้คนตรวจ"** ไม่ใช่ข้อมูลที่พร้อมนำเข้า
สิ่งที่ `review_notes` ให้คือ **รู้ว่าต้องไปดูตรงไหน** แทนที่จะต้องตรวจทุกช่อง

รายละเอียดและทางเลือกในการแก้: [docs/OCR_THAI.md](docs/OCR_THAI.md)

## วิธีที่ระบบอ่านตาราง

ฟอร์มพวกนี้เป็นตารางพิมพ์ที่กรอกด้วยลายมือ จึงใช้วิธีคนละแบบกับ parser เดิม:

1. **แก้หน้าเอียง + หาเส้นตาราง** (`workers/grid_detector.py`)
   ลายมือเขียนล้นเส้นประจำ การเดาคอลัมน์จากตำแหน่งข้อความจึงพลาด
   ระบบจึงตรวจจับ**เส้นแนวตั้งที่พิมพ์ไว้**ด้วย OpenCV เพื่อให้ได้ขอบคอลัมน์จริง
   (สแกนเอียงแค่ 1 องศา ก็ทำให้หาเส้นยาว 2000 px ไม่เจอ จึงต้อง deskew ก่อน)
2. **ระบุชนิดฟอร์มจากสัดส่วนคอลัมน์** (`workers/form_layout.py`)
   อ่านหัวตารางไม่ได้เพราะเป็นภาษาไทย จึงใช้เรขาคณิตแทน — แม่น 8/8 หน้า
3. **แบ่งแถวจากช่องตัวเลข** (`workers/balance_parser.py`)
   ฟอร์มพวกนี้**ไม่มีเส้นคั่นระหว่างแถวข้อมูล** และชื่อยามักตัดขึ้นบรรทัดใหม่
   ระบบจึงยึดช่อง ยอดยกมา/รับ/จ่าย/คงเหลือ ซึ่งมีหนึ่งค่าต่อแถวเสมอ
   เป็นตัวกำหนดแถว แล้วค่อยดึงช่องอื่นเข้ามา
   วิธีนี้ทำให้หัวตารางที่พิมพ์มาหลุดออกไปเองโดยไม่ต้องอ่านมัน
4. **ทำความสะอาดค่า + ตรวจสอบ** (`workers/balance_normalizer.py`)
   รวมถึงการตรวจ `ยอดยกมา + รับ - จ่าย = คงเหลือ` ซึ่งเป็นการยืนยันตัวเลข
   ด้วยกันเองโดยไม่ต้องพึ่งข้อมูลภายนอก

## ตั้งค่าที่เกี่ยวข้อง

| ตัวแปร | ปริยาย | |
| --- | --- | --- |
| `OCR_LANGUAGE` | `latin` | **ห้ามใส่ `th`** - PaddleOCR 2.9.1 จะ assert ทิ้ง |
| `OCR_RENDER_DPI` | `200` | ค่าที่ใช้ปรับจูนการหาเส้นตาราง เปลี่ยนแล้วต้องตรวจ tolerance ใหม่ |
| `REQUESTS_CA_BUNDLE` | `certs/ca-bundle.pem` | สร้างด้วย `scripts/setup_certs.py` |
| `DOCUMENT_ROOT` | `./data` | ไฟล์ที่อัปโหลดลงที่ `data/input/` |
| `DB_*` | PostgreSQL | ชี้ไปที่เซิร์ฟเวอร์ไหนก็ได้ ระบบใช้แค่ตาราง `balance_*` กับ `django_*` |

## ส่งต่องาน

ระบบนี้สร้างตารางของตัวเองแค่ `balance_document`, `balance_entry` และ
`django_migrations` จึงแชร์เซิร์ฟเวอร์ PostgreSQL กับระบบอื่นได้โดยไม่ชนกัน
คนรับงานแค่ตั้ง `DB_*` ใน `.env` ให้ชี้มาที่เซิร์ฟเวอร์ของตัวเอง แล้วรัน
`migrate` ไม่ต้องแก้โค้ด
